# LeadScore AI — Explainable Lead Scoring & Enrichment Layer

Built for Caprae Capital's Full Stack Developer AI-Readiness Challenge, in response to
[saasquatchleads.com](https://www.saasquatchleads.com/).

## The problem with the reference tool

SaaSquatch Leads finds and exports leads, and advertises an "AI Company Scoring" feature,
but the scoring itself is a black box — reps can't see *why* a lead is ranked the way it
is, there's no visible deduplication/validation step, and there's no bridge from "here's a
list" to "here's the first outreach message." For a sales team, a pile of unscored, unvalidated
leads in a CSV is still manual work.

## What this adds

**LeadScore AI** is a lead intelligence layer that sits on top of any scraped/exported lead
list and turns raw rows into a prioritized, explainable, actionable pipeline:

1. **Import & clean** — paste/import CSV rows. The pipeline deduplicates (by email, or by
   last name + company domain when no email exists), keeping the most complete record and
   discarding the thinner duplicate. It flags rows with missing or malformed emails/phones.
2. **Enrich** — infers company domain from email or company name, infers seniority
   (C-Level / VP / Director / Manager / IC) from job title via keyword rules.
3. **Score, explainably** — every lead gets a 0–100 ICP fit score built from four
   transparent, user-tunable factors: industry match, company size fit, seniority, and data
   completeness. Clicking a lead shows the exact breakdown and weights — not a mystery number.
4. **Tune the rules live** — the "Scoring rules" panel lets a sales/RevOps user edit target
   industries, employee-count sweet spot, and factor weights; the whole database re-scores
   instantly. This means the tool adapts to *your* ICP instead of a fixed algorithm.
5. **Act on it** — filter/sort/search, move leads through a status pipeline (New → Contacted
   → Qualified → Disqualified), one-click generate a personalized outreach email draft per
   lead, and export a prioritized CSV ready for a CRM import.

This is a "Quality First" submission: one feature area (scoring + enrichment + outreach),
built deep rather than wide.

## Why sample data instead of live scraping

The 5-hour window went into the enrichment/scoring/outreach pipeline and UI rather than a
scraper, and scraping saasquatchleads.com itself would violate its ToS. The pipeline is
**source-agnostic** — it takes any CSV of `first_name, last_name, title, company, industry,
employee_count, location, email, phone, linkedin_url` — so in production it plugs directly
into a compliant scraping job, a Clearbit/Apollo-style enrichment API, or a CRM export. A
55-row synthetic sample dataset (`public/sample_leads.csv`, generated by
`server/gen-sample-csv.js`) is bundled so the tool is demo-able immediately, including
deliberately-injected duplicates and malformed emails to prove the cleaning step works.

## Tech stack

- **Backend:** Node.js + Express, plain REST JSON API (`server/app.js`)
- **Database:** SQLite via Node's built-in `node:sqlite` module (`server/db.js`) — zero
  native dependencies (no `node-gyp`/build tools required), file-backed at `leads.db`,
  WAL journal mode for concurrent read/write safety
- **Scoring/enrichment engine:** pure functions, no external AI API dependency
  (`server/scoring.js`, `server/outreach.js`) — deterministic and explainable, and cheap to
  run at scale since there's no per-lead API cost or latency
- **Frontend:** vanilla HTML/CSS/JS (`public/`), no build step or framework — fetches the
  REST API directly. Chosen for zero-friction setup during the time-boxed challenge; the API
  is fully decoupled so a React/Vite frontend could be dropped in without backend changes
- **CSV import/export:** hand-rolled RFC 4180 parser/writer (`server/csv.js`), avoiding an
  extra dependency for a small, well-understood format

## Architecture & production deployment plan

This repo runs the whole stack locally with `npm install && npm start` for demo purposes.
For a production deployment, the plan would be:

- **Hosting:** the Express API as a small container or serverless function (e.g. AWS Lambda
  behind API Gateway, or a low-cost always-on box like Fly.io/Render for simplicity) — not a
  static host, since it needs a writable database and server-side scoring
- **Database:** move from local SQLite to a managed **Postgres** (AWS RDS or Supabase) once
  multiple users/concurrent writers are involved; SQLite's single-writer model is fine for a
  single-tenant demo but not for a multi-seat SaaS product
- **Caching:** cache `/api/stats` and `/api/icp-config` responses (both cheap to compute but
  hit on every page load) with a short-TTL in-memory or Redis cache, invalidated on
  import/config changes; the leads table itself is indexed on `email` and `icp_score` for
  fast filter/sort at scale
- **Cloud provider:** AWS (RDS for Postgres, Lambda + API Gateway or ECS Fargate for the API,
  S3 + CloudFront for the static frontend, Cognito or a lightweight JWT auth layer for
  multi-tenant access control)
- **Deployment process:** GitHub Actions CI — lint/test on PR, build on merge to `main`,
  deploy via `sam deploy`/`cdk deploy` (Lambda path) or a Docker image push to ECR + ECS
  rolling deploy (container path)

## Setup

Requires Node.js **22.5+** (uses the built-in `node:sqlite` module — no native build tools
needed).

```bash
npm install
node server/gen-sample-csv.js   # (re)generates public/sample_leads.csv
node server/seed.js             # seeds leads.db with the sample dataset
npm start                       # http://localhost:3000
```

Or skip seeding and use the "Import leads" → "Load sample dataset" button in the UI once the
server is running.

## Evaluation criteria mapping

| Criterion | How this addresses it |
|---|---|
| Business Use Case Understanding | Explainable ICP scoring prioritizes high-impact leads over a black-box number; status pipeline mirrors a real sales workflow |
| UX/UI | Single dashboard: filter/sort/search, inline status updates, one-click drill-down and outreach drafting — no page reloads |
| Technicality | Dedup by email/domain+name, email/phone validation, domain inference, configurable multi-factor scoring, transactional CSV import |
| Design | Clean, restrained visual system (badges, weight bars, consistent spacing) rather than a generic admin-table look |
| Other | Live-tunable scoring weights (adapts to any company's ICP, not fixed logic), auto-drafted personalized outreach per lead, ethical/ToS-safe use of synthetic data for the demo |
